# R3V native attended public Flat two-draw cell procedure

The public Flat two-draw cell carries a Vulkan `Flat` varying from the
application-shaped surface to RS482 silicon through the CPU delivery
route: a command buffer records two render passes with a draw each
under one pipeline whose vertex output and fragment input are decorated
`Flat`, the vertex module writes the doubled position as the varying, so
the three vertices carry three distinct saturated colors, and each pass
draws the reference triangle in its own vertex order, so the provoking
vertex -- the first, under the Vulkan core provoking-vertex rule --
differs between the passes.  `r3v_post_vs_lower_triangles` replicates
the provoking vertex's varying into the other two records ahead of the
clip-space carrier; the hardware keeps the first-draw contract's
Gouraud `GA_COLOR_CONTROL` and its TEX0 route, and interpolating three
equal records yields the one value.  A target whose whole interior holds
its pass's first-vertex color, with neither other input color anywhere,
is therefore the receipt for end-to-end Vulkan `Flat` through CPU
provoking-value replication.  It is no receipt for hardware flat
shading: no register selects a provoking vertex on this route.

`docs/hardware/r3v-native-attended-cell-procedure.md` carries the
boundary statement, the host preconditions, the substrate admission
table, the identity freeze, the arming conjunction, the rollback rules,
and the retained-record layout;
`docs/hardware/r3v-native-attended-public-two-draw-procedure.md` carries
the public two-draw recording contract this cell inherits.  This
document adds only what the Flat varying changes.

## Cell identity

- Runner: `r3v_native_attended_public_flat_two_draw <dir>` (native
  build), taking the evidence directory as its one argument.
- Arming digest source: `r3v_native_arming_runner
  --multi-pass-public-flat <dir>` emits
  `r3v_native_multi_pass_public_flat_reference` through
  `r300_tcl_bypass_triangle_clip_space_multi_pass_emit`: both passes the
  reference shape carrying the TEX0 varying record, each pass emitted
  through the cell family's varying form, the second bound to merged
  indices 2 and 3.  The attended runner prints the same digest on its
  `[shape]` line and the recorded stream's digest beside it on its
  `[record]` line; the two agree or the runner exits 2 ahead of any
  ioctl.  The vertex order rides the vertex stream, so one emitted
  stream covers both passes.
- Interface record: the `[interface]` line prints the BLAKE3 of the
  pipeline's serialized `r3v_shader_interface_link` beside its masks;
  the runner requires `varying_mask=0x1 flat_mask=0x1
  post_vs.flat_mask=0x1 provoking=0` and refuses otherwise.  The record
  is the one `r3v_shader_interface_test` pins for the Flat pair.
- Modules: `r3v_reference_vertex_flat_saturated_spirv`
  (`tint = fma(position, 2, 0)`, `Flat` on location 0) and
  `r3v_reference_fragment_flat_spirv` (`color = tint`, `Flat` on
  location 0), both regenerated by `shaders/generate_reference_spirv.py`.
- Vertex payload: the reference triangle A `(-0.75, -0.75)`,
  B `(0.75, -0.75)`, C `(0, 0.75)` in NDC with `z = 0`, `w = 1`, twice
  in one buffer: records 0..2 in the order B, C, A for the first pass
  and 3..5 in the order C, A, B for the second, drawn with
  `firstVertex` 0 and 3.  Doubling and the color buffer's UNORM8 clamp
  map the vertices to A `0xff000000`, B `0xffff0000`, C `0xff00ff00`
  in `B8G8R8A8`, each exact, so the first pass's provoking value is B's
  red and the second's C's green, while A's black is a non-provoking
  input of both and each pass's provoking color is the other pass's
  non-provoking one.
- Recording contract on the drm-shim:
  `r3v-native-public-flat-two-draw-record` runs the runner to its
  recording boundary and requires the digest and interface agreement;
  `r3v-native-public-surface` armed-submits the same command buffer on
  the shim and requires each pass's carrier to replicate its own
  provoking vertex's doubled position in every record and to hold the
  other pass's in none.
- Load-op clear and seeding: both targets carry the sentinel
  (`0xa5a5a5a5`) before the submission, as the public two-draw cell.

## Declarations

- `R3V_NATIVE_SUBMIT_HAZARD_ACCEPTED=1`
- `R3V_NATIVE_AUTHORIZED_IB_BLAKE3=<digest r3v_native_arming_runner
  --multi-pass-public-flat reports>`
- `R3V_NATIVE_AUTHORIZED_KERNEL_RELEASE=<uname -r>`
- `R3V_NATIVE_AUTHORIZED_MODULE_SRCVERSION=<loaded radeon srcversion>`
- `R3V_NATIVE_MANIFEST_DIR=<fresh evidence directory>`

Every `R3V_NATIVE_R2VB_*_EXPERIMENTAL` gate stays unset: the runner
refuses ahead of the token when one is open, because the Flat lowering
lives on the CPU route alone.

## Arming

1. `r3v_native_attended_public_flat_two_draw "$dir" --record-only` on
   the host build, and require `record: ACCEPTED` after a `[record]`
   line whose two digests agree and an `[interface]` line with
   `flat_mask=0x1`.
2. `r3v_native_arming_runner --multi-pass-public-flat "$dir"` with the
   declarations unset; retain the closed report.
3. Export the declarations from that report.
4. Rerun the arming runner and require `verdict: armed`.
5. Record the dmesg window, then run
   `r3v_native_attended_public_flat_two_draw "$dir"`.

## Predictions

If the replication route delivers, the `[record]` line reports the
recorded and emitted digests equal with the multi-pass kind,
`references=4`, and `deferred_draws=2`; the first target under
`0xffff0000` and the second under `0xff00ff00` each report
`coverage_exact=1 canary=1 interior=1152 analytic=1152 exterior=2944
mismatch=0`; every `under-non-provoking` line reports `interior=0`;
the second centroid reads `0xff00ff00`; `vkQueueSubmit` returns 0; the
dmesg delta is zero; the boot id is unchanged; and the watchdog reads
`inactive` afterward.

## Falsifiers

- The `[record]` digests differ, or the `[interface]` masks are not
  one Flat varying: the runner exits 2 with the attempt unspent, and
  the recording is the finding.
- An `under-non-provoking` line with `interior` above zero: the route
  selected another vertex, or the varying interpolated across the
  three inputs; the interior's own-color mismatch count names the
  pixels.  The route is classified by that outcome, not adjusted
  toward a pass.
- A target `coverage_exact=1` under the other pass's provoking color:
  state crossed the pass boundary.
- The second target holding the sentinel over the whole extent: the
  command processor never reached the second cell.
- `canary_pass=0` on either target: a write outside the render extent.
- A nonzero dmesg delta or a lockup ends the boot under the shared
  procedure's rollback rules.

## Retained record

The shared procedure's record plus `first_target.bin` and
`second_target.bin`, each the shape's full footprint including the
canary row.

## Result

The cell holds its silicon receipt from one attended submission on
RS482, boot `e5fc857e-4aa3-42e7-b3e5-7f31e2250f53`, mesa main
`ae2e0183f69`, under an arming report matching all five declarations
against cell blake3 `8a0c4f37` and an `[interface]` line reading
blake3 `096d66a9` with `varying_mask=0x1 flat_mask=0x1
post_vs.flat_mask=0x1 provoking=0`.  Every predicted value held: the
`[record]` line agreed (472 dwords, four references, two deferred
draws); the first target under `0xffff0000` and the second under
`0xff00ff00` each read `coverage_exact=1 canary=1 interior=1152
analytic=1152 exterior=2944 mismatch=0`; all four
`under-non-provoking` lines read `interior=0`; the second centroid
read `0xff00ff00`; `vkQueueSubmit` returned 0; the dmesg delta was
empty; the boot was unchanged; and the SB600 counter, armed across
`DRM_IOCTL_RADEON_CS` through fence completion for 113 us on the
production module, read `inactive` afterward.

So every judged interior pixel of each target equals that pass's
first-vertex value, no pixel equals either non-provoking input, no
pixel carries the other pass's provoking value, and the exterior and
canary stay at the sentinel.  The receipt proves end-to-end Vulkan
`Flat` through CPU provoking-value replication; it proves nothing
about hardware flat shading, whose register path the route leaves at
the contract's Gouraud value.  Bundle: steinmarder-r300
`src/re/r300/results/r3v-native-public-flat-two-draw-first-delivery-rs482`.

A direct `GA_COLOR_CONTROL` / RS lowering that keeps three distinct
vertex values cannot reproduce this route's command bytes: it reroutes
the varying from `TEX0` into a color lane and changes RS and GA state.
Its oracle is therefore render-target equality with this receipt's
targets, under its own frozen emitter digest, parser replay, state
mutations, and silicon receipt.
