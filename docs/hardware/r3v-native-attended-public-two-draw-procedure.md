# R3V native attended public two-draw cell procedure

The public two-draw cell is the rung-7 remainder's public-route
mechanism on silicon: a command buffer that records two render passes
with a draw each through the application-shaped Vulkan surface -- two
images, one render pass, two framebuffers, one pipeline over each
admitted fragment module, one vertex buffer, two draws -- and submits
the concatenation the recorder's two-pass arm already executed.  The
recorder arm proved the appended cell runs; this arm proves the public
route records that same stream, because the runner digests the
recorded indirect buffer before the submission and refuses unless it
equals the offline emitter's, so the authorization names the bytes the
command processor reads.

`docs/hardware/r3v-native-attended-cell-procedure.md` carries the
boundary statement, the host preconditions, the substrate admission
table, the identity freeze, the arming conjunction, the rollback rules,
and the retained-record layout;
`docs/hardware/r3v-native-attended-multi-pass-procedure.md` carries
the two-pass cell's kind, predicate, and falsifiers.  This document
adds only what the public route changes.

## Cell identity

- Runner: `r3v_native_attended_public_two_draw <dir>` (native build),
  taking the evidence directory as its one argument.
- Arming digest source: `r3v_native_arming_runner --multi-pass-public
  <dir>` emits `r3v_native_multi_pass_public_reference` through
  `r300_tcl_bypass_triangle_multi_pass_emit`: both passes the reference
  shape, the first under the reference fragment module's constant
  (opaque green, `0xff00ff00` in `B8G8R8A8`) and the second under the
  blue module's (`0xff0000ff`), the second bound to merged indices 2
  and 3.  The attended runner prints the same digest on its `[shape]`
  line and, after recording, the recorded stream's digest beside it on
  its `[record]` line; the two agree or the runner exits 2 ahead of
  any ioctl.
- Cell kind: `R3V_NATIVE_CELL_KIND_TRIANGLE_MULTI_PASS`, reached by the
  public route's own recording: the first pass's draw installs its
  render-shape cell and the second pass's appends through
  `r3v_native_cmd_buffer_append_ib`.  Each pass's deferred draw owns
  its carrier, so the four references are carrier, target, carrier,
  target in record order under the winsys first-add rule, which is the
  (2, 3) binding.
- Fragment modules: `r3v_reference_fragment_spirv` (green) and
  `r3v_reference_fragment_blue_spirv` (blue) in
  `r3v_native_reference_spirv.h`, both regenerated by
  `shaders/generate_reference_spirv.py`.  Two modules are what keep
  each target naming the pass that wrote it; one module in both passes
  would collapse the crossed-constant falsifier.
- Recording contract on the drm-shim: `r3v-native-public-two-draw-record`
  runs the runner to its recording boundary and requires the digest
  agreement; `r3v-native-public-surface` records the same two-draw
  command buffer and asserts dword equality against the emitter.
- Load-op clear: both passes clear to the sentinel
  (`0xa5 / 255` per channel).  The public draw path realizes a load-op
  clear as a host fill of the target footprint ahead of the device
  draw, so the exterior and canary predictions are the sentinel on
  either realization, and the runner seeds both allocations with it as
  well.
- Vertex payload: the reference four-dword position records in one
  vertex buffer both passes bind; the buffer's memory is no reference
  of the submission because each pass gathers into its own carrier.

## Declarations

- `R3V_NATIVE_SUBMIT_HAZARD_ACCEPTED=1`
- `R3V_NATIVE_AUTHORIZED_IB_BLAKE3=<digest r3v_native_arming_runner
  --multi-pass-public reports>`
- `R3V_NATIVE_AUTHORIZED_KERNEL_RELEASE=<uname -r>`
- `R3V_NATIVE_AUTHORIZED_MODULE_SRCVERSION=<loaded radeon srcversion>`
- `R3V_NATIVE_MANIFEST_DIR=<fresh evidence directory>`

## Arming

1. `r3v_native_attended_public_two_draw "$dir" --record-only` on the
   host build, and require `record: ACCEPTED` after a `[record]` line
   whose two digests agree.
2. `r3v_native_arming_runner --multi-pass-public "$dir"` with the
   declarations unset; retain the closed report.
3. Export the declarations from that report.
4. Rerun the arming runner and require `verdict: armed`.
5. Record the dmesg window, then run
   `r3v_native_attended_public_two_draw "$dir"`.

## Predictions

If the public route records the emitter's stream and the concatenation
executes, the `[record]` line reports the recorded and emitted digests
equal with `kind` the multi-pass kind, `references=4`, and
`deferred_draws=2`; both `[oracle]` lines for a target under its own
constant report `coverage_exact=1 canary=1 interior=1152 analytic=1152
exterior=2944 mismatch=0`; both crossed lines report
`coverage_exact=0 mismatch=1152`; the second centroid reads
`0xff0000ff`; and the dmesg delta is zero.

## Falsifiers

- The `[record]` digests differ: the public route records a stream the
  emitter does not reproduce; the runner names the differing dwords and
  exits 2 with the attempt unspent, and the recording is the finding.
- A target exact under the other pass's constant: state crossed the
  pass boundary; the concatenation's contract is the finding.
- The second target holding the sentinel over the whole extent: the
  command processor never reached the second cell.
- `canary_pass=0` on either target: a write outside the render extent.
- A nonzero dmesg delta or a lockup ends the boot under the shared
  procedure's rollback rules.

## Retained record

The shared procedure's record plus `first_target.bin` and
`second_target.bin`, each the shape's full footprint including the
canary row.
